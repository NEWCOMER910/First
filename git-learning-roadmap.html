Git 十四天学习路线

给大一新生的时间盒版本：每天 45–60 分钟，十四天累计约 11 小时，学完能独立用 Git 管作业、写脚本、带小组项目。

总时长 ≈ 11 小时 节奏 每天 45–60 分钟 核心命令 9 个 结业标准 独立完成一次小组协作

先建立一个心智模型，再背命令。Git 只有四个区域：工作区 → 暂存区 → 本地仓库 → 远程仓库。 所有命令本质上都是"把改动从一个区搬到另一个区"。看懂这条链路，命令就不会记混。

一、为什么大一就要学 Git

不是为了写代码才需要 Git。对你来说，它解决的是这四类很具体的事：

你正在经历的事没有 Git 的痛苦有 Git 之后
课程论文 / 实验报告改 N 版文件夹里躺着"报告_final2_最终版真的最终.docx"一条时间线，随时回到任意一版，还能看出改了什么
Python 数据处理脚本改完跑不通了，却回不到昨天能跑的那一版每次能跑就 commit，脚本与结果一一对应，可复现
小组作业 / 大创 / URF微信互传压缩包，最后人工合并，谁改了什么全靠记每人一个分支，PR 合并，改动可追溯、可回滚
大二大三找实习 / 推免材料拿不出能证明自己做过什么的东西GitHub 主页就是作品集，commit 记录是真实履历

海洋、地学这类专业越往后越依赖脚本处理和团队协作，Git 属于"早学两周、省四年事"的典型。

三、四阶段详解

①

本地仓库：一个人的版本管理

Day 1–3 · 约 2.5 小时 · 目标：建立"提交快照"的习惯

要掌握的命令

  • git init 建仓库
  • git status 看当前状态（最常用）
  • git add 放进暂存区
  • git commit -m 提交快照
  • git log --oneline 看历史
  • git diff 看改了什么
  • .gitignore 忽略文件

动手任务（必做）

  • 新建一个文件夹，写一份 Markdown 笔记，连做 5 次提交
  • 故意删掉一段内容，再用 git restore 找回来
  • 写 .gitignore，忽略 __pycache__/、.DS_Store、大文件
  • 用 git diff 对比两次提交之间差了什么

验收标准

  • 能口述工作区 / 暂存区 / 本地仓库三个区分别装了什么
  • 能在 git log 里定位并恢复到任意一次提交
  • commit 信息写的是"做了什么 + 为什么"，不是"修改"
②

分支与回退：敢放心折腾

Day 4–6 · 约 2.5 小时 · 目标：把"实验"和"成品"隔开

要掌握的命令

  • git branch / git switch 开分支
  • git merge 合并分支
  • 读懂并解决冲突（<<<<<<<）
  • git stash 临时存草稿
  • git reset --soft / --hard 回退
  • git revert 反向提交（已推送时用）
  • git reflog 终极后悔药

动手任务（必做）

  • 从 main 开一个 feat- 分支，改同一行制造冲突，然后手工解决
  • 改到一半要切分支，用 git stash 存起来再 stash pop
  • reset --hard 回退一次提交，再用 reflog 把它找回来
  • 理解 reset 和 revert 的区别：一个改写历史，一个追加历史

验收标准

  • 遇到冲突不慌，能判断该留哪一段
  • 知道 reset --hard 危险，动手前会先确认 reflog 能救回来
  • 养成"新想法先开分支"的肌肉记忆
③

远程与协作：和别人一起写

Day 7–10 · 约 3 小时 · 目标：独立完成 clone → 改 → PR 全流程

要掌握的命令

  • 配 SSH key（一次搞定，之后免密）
  • git clone 拉仓库
  • git remote -v 看远端
  • git push / git pull
  • git fetch 只看不合并
  • Fork + Pull Request
  • VS Code 图形化界面（辅助，不替代命令行）

动手任务（必做）

  • 注册 GitHub，配好 SSH，把本地仓库推上去
  • 在电脑另一个目录再 clone 一份，改完 push，回到原目录 pull 下来
  • Fork 任意一个开源仓库（文档类即可），改个错别字，提第一个 PR
  • 体验一次"push 被拒绝 → 先 pull → 再 push"

验收标准

  • 能说清 pull = fetch + merge
  • 能独立走完：开分支 → 提交 → push → 提 PR → 合并
  • 知道 .gitignore 要写在第一次 commit 之前才最省事
④

真实项目：用起来才算学会

Day 11–14 · 约 3 小时 · 目标：把 Git 变成默认工作方式

选一个真实载体

  • 一门课的编程作业 / 实验报告
  • 你正在写的 Python 数据处理脚本
  • 小组项目或大创的雏形仓库
  • 一份持续更新的读书 / 文献笔记库

配套动作

  • 写一份 README：项目是什么、怎么跑
  • 约定分支命名：main / dev / feat-xxx
  • 约定 commit 规范：动词开头，一行说清
  • 把队友拉进来，真实产生一次冲突并解决

验收标准

  • 连续 7 天有 commit 记录（GitHub 贡献图出现绿色）
  • 能把 add / commit / push 三件套讲给没学过的同学听懂
  • 遇到报错先看提示信息，而不是直接复制粘贴问人

四、应用场景对照表

这是最该记住的一张表——把"什么情况"和"用什么"直接对上号，比背命令参数有用得多。

场景Git 怎么帮你你会用到的命令
报告 / 论文反复改 每改完一节就提交一次，导师说"还是上一版好"时能一秒切回去 git diff · git log -p · git checkout <commit> -- 文件
数据处理脚本 脚本进 Git，原始数据和大文件不进；脚本版本与出图结果一一对应，结果可复现 .gitignore · git tag v1.0 · git log
小组作业 / 大创 每人一条分支并行写，用 PR 合并，队友互相 review，谁改了什么一目了然 git switch -c feat-xxx · git push -u origin · Pull Request
改崩了 / 误删文件 只要曾经 commit 过，几乎都能找回来——Git 最难丢的是历史 git reflog · git reset · git restore
宿舍电脑 / 实验室机器切换 一处 push，另一处 pull，不用 U 盘和微信传文件 git push · git pull · git clone
参与开源 / 建个人主页 Fork 别人的仓库改完提 PR；自己的项目攒起来就是简历 Fork · git remote add upstream · Pull Request
作业怕被抄 / 未公开内容 用私有仓库，一样享受版本管理，不影响提交作业 Private repository · git remote set-url

五、只需要先背这 9 个命令

二八定律在 Git 上特别明显：这 9 个命令覆盖你 80% 的日常操作，其余的用到再查。

git status              看现在是什么状态（不知道干啥就先敲这个）
git add <文件>          把改动放进暂存区
git commit -m "说明"     提交一次快照
git log --oneline       看提交历史
git diff                看具体改了什么
git restore <文件>      撤销工作区的改动
git switch -c <分支名>   新建并切换到分支
git merge <分支名>       把分支合进来
git push / git pull     和远程同步

再加一个救命命令：git reflog——它记录了你在这台机器上做过的每一次 HEAD 移动，是几乎所有误操作的后悔药。

六、新手最常踩的六个坑

1. commit 信息写"修改""更新" —— 三个月后你完全看不懂。改成"修复温度单位换算错误""补充 2024 年航次数据"。

2. 把数据集 / 大文件推上去 —— 仓库会变得极难 clone。第一次 commit 前就写好 .gitignore，大文件用 Git LFS 或单独存。

3. 直接在 main 上开发 —— 一旦写崩就是灾难。任何新想法都先开分支，跑通了再合并。

4. 随手 reset --hard —— 未提交的改动会直接消失。回退前先 git stash 或确认改动已 commit。

5. 看到 conflict 就慌 —— 冲突标记 <<<<<<< 和 >>>>>>> 之间只是两个版本的同一段内容，删掉标记、保留你要的，然后 add + commit 即可。

6. 不 pull 就 push —— 必然被拒。正确顺序永远是：先 pull，再 push。

七、时间控制的三条原则

固定时长，不做完也停

每天 45–60 分钟，到点就停。Git 是肌肉记忆，靠的是连续多天反复用，不是一次性学通宵。

学完立刻用，不用就忘

每学一个命令，当天必须在一个真实文件上敲一遍。只看教程不动手，两周后归零。

跳过高级话题

rebase 交互式变基、cherry-pick、submodule、钩子脚本——大一阶段全部跳过，遇到再说。

如果只有 3 天（压缩版）

时间内容产出的能力
第 1 天 · 2h安装配置 + 四区模型 + add/commit/log/diff能给自己的文件做版本管理
第 2 天 · 2h分支 + 合并冲突 + reset/reflog敢改、敢回退、丢不了东西
第 3 天 · 2hGitHub + SSH + clone/push/pull + 第一个 PR能和人协作、有公开作品

压缩版能让你"能用"，但缺少第四阶段的真实项目打磨，容易在第一次真实冲突时卡住。有时间还是走完十四天。

九、学完之后

十四天结束时，你不应该去学更多命令，而是去做更多项目。接下来的优先级：

  • 把下学期所有编程类作业默认放进 Git，让 commit 变成本能
  • 给实验室 / 课题组的数据处理流程建一个带 README 的仓库，这就是科研可复现性的起点
  • 大创或 URF 立项时，直接在第一天就建仓库、拉队友进来
  • 等到需要时再回头学：交互式 rebase 整理提交历史、cherry-pick 挑提交、tag 打版本、submodule 管子项目

一句话记住这套路线：前三天学会"不丢东西"，第四到六天学会"敢乱改"，第七到十天学会"和人一起写"，最后四天把它变成你的默认工作方式。
